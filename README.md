# Keitaro Wrapper

Тестовое Adrobot: создание кампаний и редактор офферов с локальными черновиками.
Backend — FastAPI + SQLAlchemy 2, frontend — Next.js 16 / React 19 / TypeScript.
Локальная база — SQLite, изменение схемы — Alembic.

## Возможности

- Создание кампании с префиксом `test_tadzhibov_`, доменом, группой и источником.
- Два потока: выбранная страна → Google; остальной трафик → выбранный оффер.
- Загрузка существующих кампаний, потоков и каталога офферов из Admin API.
- Поиск оффера по ID и названию с автодополнением.
- Добавление, удаление из потока, локальный архив и восстановление.
- Равномерное распределение целых процентов с точной суммой 100%.
- Закрепление доли, отдельные кнопки публикации и отмены для каждого потока.
- Сохранение черновиков после обновления страницы и перезапуска backend.
- Обнаружение устаревших локальных версий и внешних изменений состава потока.
- При Fetch исчезнувшие из Keitaro офферы становятся архивными локально.

## Требования

- Python 3.12+; проверено на Python 3.14.
- Node.js 22+ и npm.
- API-ключ тестового Keitaro. Для предоставленного эмулятора отдельная лицензия и VPS не требуются.

## Backend: установка, миграции, запуск

Из корня проекта перейдите в backend:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` заполните `KEITARO_API_KEY`. Ключ остаётся на backend: Next.js и браузер
его не получают. `.env`, база и виртуальное окружение исключены из Git.

```dotenv
KEITARO_BASE_URL=https://keitaro-for-tests.etolegko.com/admin_api/v1
KEITARO_API_KEY=https://keitaro-for-tests.etolegko.com/admin/#!/campaign.editor/<id>
CAMPAIGN_PREFIX=test_tadzhibov_
DATABASE_URL=sqlite:///./keitaro.db
REQUEST_TIMEOUT=20
```

Примените миграции и запустите один worker:

```bash
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8011
```

Swagger: <http://127.0.0.1:8011/docs>. Проверка запуска: <http://127.0.0.1:8011/api/health>.
Схема не создаётся автоматически при старте: для новой базы обязательна команда миграции.

## Frontend: запуск

В другом терминале, из корня проекта:

```bash
cd frontend
npm ci
BACKEND_URL=http://127.0.0.1:8011 npm run dev -- --port 3011
```

Откройте <http://127.0.0.1:3011>. Относительные запросы `/api/*` проксируются
через Next.js к FastAPI; отдельная настройка CORS не нужна.
Порты выбраны так, чтобы не занимать распространённые 3000 и 8000.
Без `BACKEND_URL` frontend использует backend по адресу `http://127.0.0.1:8000`.

Для production-сборки задавайте одинаковый `BACKEND_URL` при build и start.
Команды выполняются из корня проекта:

```bash
cd frontend
BACKEND_URL=http://127.0.0.1:8011 npm run build
BACKEND_URL=http://127.0.0.1:8011 npm run start -- --port 3011
```

## Как проверить вручную

1. Откройте «Новая кампания», задайте суффикс названия, страну и оффер из каталога.
   Префикс добавляется автоматически. Нажмите «Создать в Keitaro».
2. В редакторе проверьте два потока. Поток без офферов показан информационно:
   редактор не меняет его фильтры или перенаправление.
3. Добавьте второй оффер. Доли станут 50/50, поток отметится как черновик.
   В Keitaro изменений пока нет.
4. Нажмите «Отменить»: новая связь исчезнет из черновика.
5. Добавьте два оффера, закрепите первому 25%. Остальные получат 38% и 37%.
6. Нажмите «Опубликовать», затем Fetch Streams. Проверьте состав и доли в админке.
7. Уберите один оффер и опубликуйте: в Keitaro его больше нет в потоке,
   локально он остаётся с долей 0% и кнопкой «Вернуть».
8. Верните его, опубликуйте и выполните Fetch. Закреплённые 25% сохраняются.
9. Удалите оффер из потока непосредственно в Keitaro и выполните Fetch:
   локальная запись станет архивной, а не исчезнет.

Журнал эмулятора содержит запросы приложения; проверяющий видит тот же журнал.
Не добавляйте секреты к названиям кампаний или другим отправляемым данным.

## Правила и принятые решения

- `baseline` — последнее синхронизированное состояние связей потока;
  `draft` — рабочее состояние. Оба сохраняются в SQLAlchemy JSON-колонках.
  Полные снимки позволяют атомарно откатить добавления, удаления и закрепления.
- Архивируется **связь оффера с потоком**. Общий каталог офферов не изменяется.
- Cancel восстанавливает baseline, включая закрепления. Новые неопубликованные
  связи исчезают из локального состояния.
- Fetch запрещён при наличии черновиков в кампании, чтобы явно не терять работу.
- Закреплённые активные доли вычитаются из 100. Остаток делится между свободными
  офферами; целочисленный остаток получают первые свободные офферы в локальном
  порядке. Архивные получают 0% и в расчёте не участвуют.
- Удаление последнего активного оффера запрещено. Сумма закреплений больше 100%
  запрещена. Если все активные доли закреплены, их сумма обязана равняться 100%.
  Нулевые доли разрешены. Эти крайние случаи в видео не определены; здесь выбрана
  явная валидация с сообщением пользователю.
- При Remove закрепление сохраняется в архиве; Restore возвращает его, если
  распределение остаётся допустимым. Иначе сначала нужно освободить другие доли.
- При Fetch внешние доли принимаются как актуальные; сохранённое закрепление
  привязывается к полученной доле. Для архивных офферов оно сохраняется.
- Push отправляет **весь активный состав** через `PUT /streams/{id}` и не включает
  поля фильтров, схемы или перенаправления. После записи выполняется проверка GET.
- Перед Push удалённое состояние сравнивается с baseline. При конфликте — 409,
  без перезаписи чужих изменений. Если после потерянного ответа удалённое
  состояние уже совпадает с черновиком, повторный Push просто подтверждает его.
- Запросы записи автоматически не повторяются. При частично созданной кампании
  показывается её ID: нужно проверить её в админке перед новой попыткой.

## Тесты и миграции

Из корня проекта:

```bash
cd backend
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
pytest -q
alembic check
```

Тесты используют временные базы и fake/MockTransport вместо живого API.
Проверяются создание потоков, расчёты и округление, архив, Cancel, Fetch,
ошибки публикации, потерянное подтверждение, конфликты версий и перезапуск backend.

Команды работы со схемой выполняются из `backend/`:

```bash
alembic current
alembic upgrade head
alembic revision --autogenerate -m "describe change"
```

`alembic downgrade base` удалит локальные таблицы вместе с черновиками и архивом;
используйте только на одноразовой тестовой базе. Данные Keitaro это не затрагивает.

## Границы решения

Приложение предназначено для локального запуска одним пользователем, один worker
FastAPI. Короткие операции редактора и публикация сериализуются локальным lock;
SQLAlchemy version counter дополнительно обнаруживает устаревшие записи.
Для многопользовательского размещения понадобятся отдельная авторизация,
PostgreSQL и межпроцессная блокировка публикации. Публиковать локальный backend
в интернет без такой доработки не следует.

Проверка перед записью не является удалённой транзакцией: изменение Keitaro
между GET и PUT полностью исключить без поддержки условных запросов API нельзя.
Тестовый стенд не обрабатывает клики, поэтому гео-маршрутизация проверяется по
созданным фильтрам и настройкам потоков. Приложение не запрашивает отсутствующие
на эмуляторе отчёты, триггеры, архив или справочники типов потоков.

Разработка велась с помощью Codex. Проверки, обозначенные выше, выполняются
отдельно от генерации кода; API-ключи в репозиторий не включаются.
